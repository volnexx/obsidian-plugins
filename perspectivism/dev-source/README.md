## 1. Назначение

**Perspectivism — плагин Obsidian, который сортирует и размечает строки текущей заметки, а при явной команде `scan on` ищет совпадения во всём хранилище.**

Верхняя группа содержит строки с выбранной перспективой. Нижняя группа содержит остальные строки. Между группами вставляется одна пустая строка.

Что является применением: открыть заметку с перспективой `купить` и получить в ней строки с перспективой `купить` из остальных заметок хранилища.

Что не является применением: копирование целых заметок, поиск по вложениям или изменение исходных заметок.

## 2. Формат служебного блока и шаблон

**Служебный блок — последовательность строк, начинающаяся со строки `ppp` и заканчивающаяся перед первой пустой строкой.**

```text
ppp
- [ ] p
scan on
купить
сделать

```

**Шаблон строки — первая строка после `ppp`, в которой латинская буква `p` обозначает место для найденной строки.**

**Команда `scan on` — отдельная строка сразу после шаблона, которая разрешает собирать совпадения из других заметок.**

Без `scan on` плагин по умолчанию не читает остальные заметки и не добавляет отсутствующие строки. Сортировка, рычаги `∧` и `∨`, а также пошаговый разбор текущей заметки продолжают работать. Ранее собранные строки автоматически не удаляются.

Если команда присутствует, перспективы начинаются со следующей строки после `scan on`. Если команды нет, перспективы начинаются сразу после шаблона. Каждая перспектива записывается на отдельной строке. Служебный блок может находиться в любом месте заметки. После обработки плагин переносит его вниз и не смешивает его строки с содержанием заметки. Если блок находится в конце файла, завершающая пустая строка необязательна.

Перед переносом плагин составляет строку `Название исходной заметки – найденная строка`. Расширение `.md` и путь к папке в название не входят. Если шаблон содержит `p`, каждая такая буква заменяется всей составленной строкой. Если в шаблоне нет `p`, составленная строка переносится без дополнительного оформления.

Что является включением сбора: отдельная строка `ppp`, затем шаблон `- [ ] p`, затем `scan on`, перспективы `купить` и `сделать`, затем пустая строка.

Что не является включением сбора: `scan on` перед шаблоном, после первой перспективы или на одной строке с `p`.

## 3. Автоматический анализ

Анализ запускается только при наличии `scan on`: сразу после ввода команды, при открытии заметки и при переходе на уже открытую вкладку заметки. Результат помещается перед строкой `ppp`. Без `scan on` обход хранилища не начинается. Удаление команды во время анализа отменяет текущий обход. Плагин не добавляет в заметку служебные отметки или другие технические строки.

При следующем анализе предыдущая подборка полностью заменяется. Чтобы отличать её от собственного текста пользователя, плагин хранит список вставленных строк в своём файле данных.

Перед новой вставкой плагин удаляет все экземпляры строк из предыдущей и новой подборок, независимо от их положения, а затем вставляет каждую итоговую строку ровно один раз. Поэтому несколько старых слоёв одинаковых строк сворачиваются в один слой. Это правило действует и тогда, когда сведения о старой подборке отсутствуют во внутренних данных, но строки входят в заново вычисленный результат.

Заметка, содержащая собственный служебный блок `ppp`, не используется как источник для другой заметки. Благодаря этому две собирающие заметки не могут копировать результаты друг у друга. Каталог настроек Obsidian, включая `.obsidian/plugins/`, также никогда не анализируется.

Обновление подборки не переносит курсор в начало заметки. Плагин изменяет только отличающийся участок текста и сохраняет положение курсора и выделение с учётом добавленных или удалённых строк.

## 4. Работа рычагов

**Рычаг перспективы — кнопка в правой панели, которая добавляет перспективу в общий отбор или убирает её из отбора.**

При наведении на карточку перспективы от центра появляется сетка мерцающих квадратных частиц. Цвета берутся из текущей темы Obsidian; частицы находятся под текстом и рычагом, поэтому не мешают чтению и нажатию. При уходе курсора частицы сжимаются и исчезают. Если в системе включено уменьшение движения, анимация отключается.

- Плагин сам открывает панель «Перспективы» справа.
- Слева от рычага каждой перспективы показывается число строк текущей заметки, в которых она присутствует.
- Отдельный ползунок без подписи над списком меняет порядок перспектив. В выключенном состоянии сохраняется порядок блока `ppp`; во включённом перспективы располагаются по убыванию числа строк.
- При одинаковом числе строк сохраняется взаимный порядок перспектив из блока `ppp`.
- Одновременно можно включить несколько перспектив.
- Над списком находятся две маленькие квадратные взаимоисключающие кнопки `∧` и `∨`, без текстовых подписей.
- `∧` включена по умолчанию: наверх поднимаются только строки, в которых присутствуют все выбранные перспективы.
- `∨`: наверх поднимаются строки, в которых присутствует хотя бы одна выбранная перспектива.
- Нажатие одной логической кнопки сразу выключает другую и пересчитывает текущий отбор.
- Сортируются все непустые строки заметки, кроме свойств и служебного блока `ppp`.
- Нажатие на выключенную перспективу добавляет её к уже выбранным перспективам и заново применяет отбор к исходному порядку.
- Нажатие на включённую перспективу убирает только её и заново применяет отбор по оставшимся перспективам.
- Если после сортировки заметка не редактировалась, выключение последней перспективы возвращает исходный порядок.
- Пока рычаг включён, автоматический анализ приостанавливается, чтобы не отменить выбранный порядок. После выключения рычага анализ запускается снова.
- Если после сортировки заметка была вручную изменена, включённые перспективы всё равно можно выключать. При выключении последней перспективы плагин сохраняет внесённые изменения и текущий порядок строк, а не восстанавливает старую копию поверх нового текста.
- После ручного изменения нельзя включить дополнительную перспективу, пока текущий отбор не выключен: это защищает внесённый текст от неоднозначной повторной сортировки.
- После ручного изменения нельзя сменить `∧` на `∨` или обратно, пока текущий отбор не выключен: операция переставила бы уже изменённые строки неоднозначно.

Например, при выбранных перспективах `купить` и `дом` в режиме `∧`:

- `купить пылесос для дома` поднимается;
- `купить телефон` не поднимается;
- `убраться дома` не поднимается.

С теми же перспективами в режиме `∨` поднимутся все три строки, потому что в каждой присутствует хотя бы одна из двух перспектив.

## 5. Пошаговый разбор строк

**Пошаговый разбор строк — режим, который показывает непомеченные строки текущей заметки по одной и позволяет дописывать выбранные перспективы в конец строки.**

Режим открывается кнопкой «Разобрать строки» в правой панели. В центральном окне сначала выбираются одна или несколько перспектив из блока `ppp`, затем нажимается кнопка «Старт».

Над кнопкой «Старт» находится рычаг «Пропускать строки с выбранной перспективой». По умолчанию он включён: если строка уже содержит хотя бы одну из выбранных перспектив, она не попадает в очередь. Когда рычаг выключен, сохраняется прежнее правило: строка исключается только при наличии всех выбранных перспектив.

При одной выбранной перспективе:

- строка, уже содержащая эту перспективу, не попадает в очередь;
- смахивание влево или клавиша `←` пропускает строку;
- смахивание вправо или клавиша `→` дописывает перспективу в конец строки;
- клавиша `↑` пропускает строку без добавления перспективы;
- под карточкой остаются две кнопки со стрелками для того же действия без смахивания.

При двух выбранных перспективах:

- порядок определяется последовательностью выбора перспектив;
- смахивание вправо или клавиша `→` добавляет перспективу, выбранную первой;
- смахивание влево или клавиша `←` добавляет перспективу, выбранную второй;
- клавиша `↑` пропускает строку без добавления перспективы;
- под карточкой показаны обе перспективы рядом с соответствующими стрелками.

При трёх и более выбранных перспективах:

- двойное нажатие по перспективе в окне выбора закрепляет её для стрелок;
- одновременно можно закрепить не более двух перспектив; после закрепления двух остальные двойные нажатия не действуют, пока одна из них не откреплена;
- первое закрепление назначает перспективу клавише `→`, второе — клавише `←`;
- если закреплены две перспективы, включается смешанный режим: закреплённые выбираются стрелками, а остальные остаются независимыми рычагами;
- включённые рычаги добавляются вместе с перспективой, выбранной стрелкой;
- клавиша `↑` в смешанном режиме пропускает строку и не добавляет ни закреплённые, ни включённые рычагами перспективы;
- на телефоне для пропуска также показывается отдельная экранная кнопка `↑`;
- уже присутствующую в строке перспективу нельзя повторно выбрать стрелкой;
- поле поиска над выбором перспектив фильтрует кнопки, не снимая выбранные и закреплённые;
- состояние незавершённого разбора сохраняется и продолжается кнопкой `▶` в заголовке правой панели;
- кнопка `↩` отменяет последний ответ разбора, если после него заметка не редактировалась вручную;
- исходный порядок отбора сохраняется между перезапусками и восстанавливается кнопкой `↶`;
- при включённом рычаге пропуска строка не попадает в очередь, если в ней уже есть хотя бы одна выбранная перспектива;
- при выключенном рычаге строка не попадает в очередь, только если в ней уже есть все выбранные перспективы;
- перспективы, уже находящиеся в строке, показаны включёнными и не добавляются повторно;
- недостающие перспективы работают как независимые рычаги;
- за один шаг можно включить и добавить сразу несколько перспектив;
- если ничего не включено, кнопка «Пропустить» переходит к следующей строке без изменения.

Каждое принятое изменение сразу записывается в заметку. Закрытие центрального окна сохраняет уже обработанные строки. Свойства заметки, пустые строки, блок `ppp` и автоматически скопированные строки не предлагаются для разбора.

Что является применением: строка `проверить код` и выбранная перспектива `прагматизм` превращаются после смахивания вправо в `проверить код прагматизм`.

Что не является применением: изменение исходной заметки строки, которую плагин автоматически скопировал из другого файла.

## 6. Пример

Целевая заметка:

```text
ppp
p
scan on
купить
сделать

```

Если в других заметках есть нужные строки, после открытия получится:

```text
Покупки – купить шампунь
Техника – купить монитор
Учёба – сделать дз

ppp
p
scan on
купить
сделать
```

Для шаблона задачи:

```text
ppp
- [ ] p
scan on
купить

```

результат будет таким:

```text
- [ ] Покупки – купить шампунь
- [ ] Техника – купить монитор

ppp
- [ ] p
scan on
купить
```

Для шаблона `**p**` название исходной заметки и найденная строка вместе будут заключены в двойные звёздочки. Например: `**Техника – купить монитор**`.

## 7. Установка

1. Полностью закройте Obsidian.
2. Удалите старую папку плагина.
3. Распакуйте папку `perspectivism` в:

   ```text
   ВАШЕ_ХРАНИЛИЩЕ/.obsidian/plugins/
   ```

4. Запустите Obsidian.
5. Откройте «Настройки» → «Сторонние плагины».
6. Включите «Perspectivism».

Архив переходной версии уже содержит перенесённый `data.json`. Не копируйте поверх него файлы из предыдущей версии.

Если правая панель была закрыта, нажмите значок отбора на левой ленте или выполните команду «Открыть панель перспектив».

Для исправления заметки, в которой старые подборки уже размножились, откройте палитру команд и выполните «Очистить и заново собрать скопированные строки в текущей заметке». Перед удалением плагин запросит подтверждение. Команда работает и при отсутствии сведений о старых строках во внутренних данных: она заново вычисляет текущую подборку, удаляет все её экземпляры и вставляет по одному.

## 8. Точные правила обработки

- Сравнение не зависит от регистра: `Купить` соответствует перспективе `купить`.
- Поиск проверяет границы перспективы, состоящей из слова или фразы.
- Перспектива `купить` соответствует строкам `надо купить монитор` и `«купить»`, но не соответствует `закупить`, `купитьмонитор` и `купить_монитор`.
- Перспектива `купить монитор` соответствует этой точной последовательности слов, если перед ней и после неё нет примыкающих букв, цифр или знака `_`.
- Анализируются только файлы Markdown.
- Сбор из других заметок выполняется только при точной отдельной строке `scan on` сразу после шаблона.
- Регистр команды не учитывается: `scan on`, `SCAN ON` и `Scan On` равнозначны.
- Без команды `scan on` остальные заметки не читаются, а отсутствующие строки не добавляются.
- Строка `scan on` является командой и не считается перспективой.
- Сама открытая заметка исключается из поиска.
- Каталог настроек Obsidian, включая файлы плагинов, исключается из поиска.
- Любая заметка с собственным блоком `ppp` целиком исключается из источников.
- Ранее созданные подборки не используются как источники.
- В заметку не записываются комментарии `<!-- ... -->` или иные технические отметки.
- Перед исходной строкой записывается название заметки-источника без `.md`, затем пробел, среднее тире `–` и ещё один пробел.
- Без `p` переносится составленная строка `Название заметки – исходная строка` без дополнительного оформления.
- При наличии `p` шаблон применяется ко всей составленной строке `Название заметки – исходная строка`.
- Первая строка после `ppp` является шаблоном и не участвует в поиске как перспектива.
- Одинаковая итоговая строка копируется только один раз. Одинаковый исходный текст из заметок с разными названиями сохраняется отдельно, поскольку названия источников различаются.
- Повтор одной строки внутри одной исходной заметки копируется один раз.
- Все старые экземпляры заново найденной строки удаляются перед вставкой её единственного экземпляра.
- Исходные заметки не изменяются.
- Если найдено больше 5000 различных итоговых строк, анализ останавливается и заметка не изменяется.
- В пошаговом режиме перспектива дописывается через один пробел в конец строки перед её конечными пробелами.
- Уже присутствующая перспектива не добавляется повторно.
- В обычном режиме нескольких рычагов порядок добавления перспектив совпадает с порядком их выбора в начале режима.
- В смешанном режиме сначала добавляется закреплённая перспектива выбранной стрелки, затем включённые дополнительные перспективы в порядке их первоначального выбора.

## 9. Исключённые заметки и слова в названиях

В настройках плагина есть поле «Исключенные заметки». В нём указываются названия заметок, которые плагин не должен использовать как источники при поиске:

```text
Черновик
Архив
Шаблоны
```

Каждое название записывается на отдельной строке. Расширение `.md` необязательно, регистр не учитывается. Проверяется точное название заметки: строка `Архив` исключает `Архив.md`, но не исключает `Архив 2026.md`. Если в разных папках есть заметки с одинаковым названием, исключаются все они.

Изменение списка не удаляет и не изменяет исходные заметки. Плагин повторно анализирует открытую целевую заметку и удаляет из её подборки строки исключённых источников.

Второе поле «Исключённые слова в названиях» исключает заметки по словам или фразам, содержащимся в их названиях:

```text
архив
черновик
старая версия
```

Каждое слово или фраза записывается на отдельной строке. Регистр не учитывается, а совпадение проверяется по границам слова. Поэтому `архив` исключает `Архив 2026.md` и `Старый архив.md`, но не исключает `Архивный материал.md`.

Что является исключением по слову: ключ `черновик` и заметка `Черновик проекта.md`.

Что не является исключением по слову: ключ `архив` и заметка `Архивный материал.md`.

## 10. Нагрузка

**Сложность анализа — объём текста всех файлов Markdown, который плагин должен прочитать один раз при каждом переходе на заметку.**

Для хранилища примерно из 800 обычных текстовых заметок это умеренная нагрузка. Основная цена — кратковременное чтение и поиск по строкам. Плагин уступает время интерфейсу после каждой сотни файлов, поэтому не должен надолго блокировать Obsidian.

## 11. Состав плагина и сборка

Для обычной установки нужны только:

- `manifest.json`;
- `main.js`;
- `styles.css`.

Для самостоятельной сборки исходного кода:

```bash
npm install
npm run check
npm test
npm run build
```
